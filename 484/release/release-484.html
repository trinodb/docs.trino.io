    Release 484 (15 Oct 2026)#

    General#

    • Add support for the JSON value constructor. (#30341)

    • Add support for the JSON_SERIALIZE function. (#30341)

    • Add the json_scalar() function. (#30341)

    • Add support for json input to JSON_EXISTS, JSON_VALUE, JSON_QUERY, and JSON_TABLE. (#30341)

    • Add support for datetime values in the JSON type and casts from json to date and time. (#30341)

    • Add support for numeric values in JSON_VALUE with RETURNING, JSON path arithmetic, and JSON path array subscripts. (#30341)

    • Allow FORMAT JSON arguments in JSON_OBJECT with WITH UNIQUE KEYS, enforcing key uniqueness in nested objects. (#30341)

    • Add support for interval types with explicit leading-field precision and up to 12 fractional-second digits. (#6754)

    • Add support for specifying the interval field range and precision when subtracting datetime values. (#6754)

    • Add support for the EXCLUDE clause in window frame specifications. (#30226)

    • Add support for a single file system cache shared by all catalogs on a node. Cache managers are configured with the cache-manager.config-files configuration property. (#29184)

    • Add support for IF NOT EXISTS in CREATE VIEW. (#28076)

    • Add support for adding comments to materialized views with COMMENT. (#31279)

    • Add support for limiting the size of the output data produced by a query with the query.max-output-data-size configuration property. (#30615)

    • Add support for returning metrics from procedures invoked with CALL. (#30749)

    • Allow resource groups and selectors with a NULL environment in the database resource group manager to match every environment. (#30873)

    • Include the user who killed, preempted, or canceled a query in the failure message when another user stops the query. (#31603)

    • Allow restoring the legacy implicit coercion from varchar to char for a session with the legacy_varchar_to_char_coercion session property. (#30708)

    • Allow restoring the legacy repair of topologically invalid input geometries in ST_Intersection(), ST_Difference(), ST_SymDifference(), ST_Union(), geometry_union(), and geometry_union_agg() with the trino.geospatial.legacy-lenient-overlay JVM system property. (#30584)

    • ⚠️ Breaking change: Preserve the case of user names in GRANT, REVOKE, SET AUTHORIZATION, and CREATE SCHEMA statements instead of converting them to lowercase. User names are compared case-sensitively with the authenticated user, so privileges granted to Alice only apply to the user Alice. Role names are still converted to lowercase. (#30567)

    • Fail queries after a single task retry instead of retrying until the task retry limit is reached when spooled exchange data is lost with retry-policy set to TASK. (#31336)

    • ⚠️ Breaking change: Retain numeric arguments as JSON numbers in JSON_ARRAY, JSON_OBJECT, and PASSING clauses instead of converting them to JSON strings. (#30341)

    • ⚠️ Breaking change: Retain numeric types and decimal scale when casting array, map, and row values to json. (#30341)

    • ⚠️ Breaking change: Retain decimal notation when casting decimal-form JSON numbers to varchar. (#30341)

    • ⚠️ Breaking change: Retain object member order and duplicate keys in json_parse() and JSON literals. (#30341)

    • ⚠️ Breaking change: Disallow construction of JSON values with more than 1,024 nested arrays and objects. (#30341)

    • ⚠️ Breaking change: Disallow JSON input containing overflowing exponent-form numbers or unpaired Unicode surrogate escapes. (#30341)

    • ⚠️ Breaking change: Remove conversion of json arguments to JSON strings in JSON_ARRAY, JSON_OBJECT, and PASSING clauses. The JSON values are used directly without requiring FORMAT JSON. (#30341)

    • ⚠️ Breaking change: Require quoting identifiers named JSON_SERIALIZE, which is a reserved keyword. (#30341)

    • ⚠️ Breaking change: Require qualifying calls written as json(x) to invoke a function instead of the JSON constructor. (#30341)

    • ⚠️ Breaking change: Limit the number of elements returned by ngrams() to 1,000,000. (#30806)

    • ⚠️ Breaking change: Reduce the maximum duration of day-time intervals to approximately 292,000 years. Subtracting timestamps that are further apart fails with an overflow error. (#6754)

    • ⚠️ Breaking change: Disallow extracting fields that are absent from an interval’s qualifier. (#6754)

    • ⚠️ Breaking change: Return the full leading field when extracting a value from an interval, such as 36 for hour(INTERVAL '36' HOUR). (#6754)

    • ⚠️ Breaking change: Truncate interval multiplication and division results to the interval’s field range. (#6754)

    • Set the process name to trino-server when running the trino-server-core distribution. (#30403)

    • Improve performance of queries involving boolean values, especially when reading or writing ORC and Parquet files. (#30299)

    • Improve performance of queries that compare the result of at_timezone() with a constant time zone against a timestamp with time zone value. (#30597)

    • Reduce memory usage for queries that compute both avg() and sum() over the same decimal column. (#30595)

    • Improve performance of queries with predicates on date_trunc() with the week or quarter unit. (#30192)

    • Improve performance of window functions that compute sum() over decimal values with a moving window frame. (#30630)

    • Improve scheduling of tasks that require no memory, such as tasks reading only metadata, when cluster memory is exhausted with fault-tolerant execution. (#30678)

    • Improve performance of queries with uncorrelated EXISTS subqueries. (#30224)

    • Improve performance of queries that filter or project dictionary-encoded data. (#30877)

    • Reduce the amount of data read for queries with filters that combine multiple conditions with AND. (#30909)

    • Improve performance of queries with joins and filters that can fail when optimizer.allow-unsafe-pushdown is enabled. (#30917)

    • Reduce memory usage of queries that redistribute dictionary-encoded data across workers. (#31056)

    • Improve performance of cross joins where one side is a subquery with LIMIT or ORDER BY ... LIMIT. (#31128)

    • Improve performance of queries with range comparisons between char columns and varchar values. (#31089)

    • Improve performance of queries with an IN predicate that compares a cast expression against a list of literals, such as CAST(ts AS date) IN (DATE '2020-01-01', DATE '2020-01-02'). (#31182)

    • Improve performance of filters on dictionary-encoded columns when each page uses only a few entries of a large dictionary. (#31200)

    • Improve performance of queries with ORDER BY when retry-policy is set to QUERY. (#30966)

    • Improve performance of queries that differ only in literal values from previously run queries. (#30465)

    • Reduce worker memory usage for queries with many operators. (#31301)

    • Reduce memory usage of dynamic filtering on varchar columns. (#31303)

    • Improve performance of queries with filters on at_timezone() over timestamp with time zone columns, including filters on views that convert such columns to a per-row time zone. (#30551)

    • Improve query planning performance for queries with many joins. The optimizer.max-reordered-joins configuration property and the max_reordered_joins session property are limited to a maximum of 62. (#31261)

    • Improve performance of BETWEEN and comparison predicates on numeric values that are implicitly cast to a wider type. (#31400)

    • Improve performance of casting between decimal values and double or real values. (#31475, #31481, #31502)

    • Improve performance of queries with conditional expressions, such as CASE or IF, that reference columns only needed when the condition is met. (#31473)

    • Improve performance of nested string concatenations. (#31465)

    • Fix failure when a JSON simplified accessor applies an item method, such as integer(), after two or more nested member accesses, for example j.a.b.integer(). (#30379)

    • Fix query failure when using try() with an argument containing nullif() or BETWEEN. (#30399)

    • Fix potential worker memory accounting leak when tasks finish, which can cause queries to block or fail with out-of-memory errors. (#30472)

    • Fix incorrect results for IF and CASE expressions that repeat a non-deterministic condition within a branch. (#30509)

    • Fix incorrect results when sum() over bigint values overflows in a window function. The query fails instead. (#30600)

    • Fix incorrect results when using AT TIME ZONE with an interval offset outside the range of -14:00 to +14:00 on time values. The query fails instead. (#9288)

    • Fix potential worker unavailability under highly concurrent workloads. (#30627)

    • Fix incorrect results for joins on char columns cast to varchar when dynamic filtering is enabled. (#30686)

    • Fix worker out-of-memory errors due to untracked memory usage for queries with large right or full outer joins. (#30790)

    • Fix incorrect results when casting some decimal values with precision of 18 or less to real. (#30130)

    • Fix failure when executing a USE statement as a prepared statement. (#30859)

    • Fix query failure when planning queries with a very large number of OR predicates. (#30709)

    • Fix missing query completion events and a potential coordinator memory leak when a worker restarts while running a query. (#30755)

    • Fix query failure for queries with a BETWEEN predicate on an expression and multiple aggregations with DISTINCT. (#30608)

    • Fix intermittent query failure with a No committed attempts found under sink output path error when using fault-tolerant execution. (#30411)

    • Fix failure of convex_hull_agg() when an input geometry is topologically invalid. (#30584)

    • Fix incorrect results or query failure for avg() over decimal values when the sum of the values exceeds the range of the type. (#30991)

    • Fix potential worker out-of-memory errors for queries with ORDER BY ... LIMIT or filters on row_number() or rank() that process wide rows. (#31014)

    • Fix incorrect results when date_add() or adding an interval to a timestamp value produces a value outside the supported range. The query fails instead. (#31002)

    • Fix incorrect results when subtracting timestamp values with a very large difference. (#31002)

    • Fix incorrect results for aggregations over outer joins without equality conditions, such as LEFT JOIN ... ON true, when the joined side produces no rows. (#30989)

    • Fix query failure instead of returning NULL when calling mod() with a zero divisor inside try(). (#31054)

    • Fix failure when using WITH SESSION to set a catalog session property for a catalog that already has session properties set. (#31045)

    • Fix failure when a SQL user-defined function ends with an IF or CASE statement that returns a value from every branch. (#30582)

    • Fix incorrect results when filtering with IF, CASE, or NULLIF expressions that contain non-deterministic conditions. (#30993)

    • Fix incorrect results for IN predicates with real NaN values, or with time with time zone and timestamp with time zone values in different time zones. (#31069, #31080)

    • Fix incorrect memory accounting for aggregations with both DISTINCT and ORDER BY clauses, which could cause workers to run out of memory. (#31039)

    • Fix workers becoming unresponsive and dropping out of the cluster when running queries with a large number of stages and tasks. (#21512)

    • Fix MERGE failing with MERGE_TARGET_ROW_MULTIPLE_MATCHES when the target table is bucketed and the query uses a partitioned join distribution. (#30639)

    • Fix incorrect results for aggregations over CASE expressions that contain non-deterministic functions. (#31121)

    • Fix incorrect results for comparisons involving year() or date_trunc() with a non-deterministic argument. (#31086)

    • Fix incorrect results for IS NOT DISTINCT FROM comparisons between a cast expression and a constant. (#31084)

    • Fix incorrect results for simple CASE expressions when the operand is NULL or NaN, or when comparing values with time zones. (#31065, #31081)

    • Fix incorrect data_type for number columns in system.jdbc.columns and in JDBC DatabaseMetaData.getColumns. (#31184)

    • Fix incorrect results for OR and IN predicates over non-deterministic expressions. (#31149)

    • Fix failure of recursive WITH queries that use a table function. (#31053)

    • Fix incorrect results for queries with multiple aggregations containing a DISTINCT clause over non-deterministic expressions. (#31151)

    • Fix try() not suppressing errors when accessing a field of a row produced by a failing expression, such as TRY(array[index].field) with an out-of-bounds index. (#31008)

    • Fix incorrect results for char values ending with a space produced by reverse() or by casting to a shorter char type. (#31190)

    • Fix query failure when comparing a varchar value cast to char with a char value. (#31187)

    • Fix incorrect results for IN and NOT IN predicates with a list of consecutive values that contains NULL. (#31068)

    • Fix incorrect results for full outer joins with a join condition when an input produces a single row. (#30988)

    • Fix incorrect results for trim(), ltrim(), and rtrim() on char values when trimming a set of characters that does not include a space. (#31004)

    • Fix potential worker memory leak when a task fails while writing its output, such as when a fault-tolerant task is aborted. (#31334, #31353)

    • Fix incorrect results and failures when casting a timestamp value before 1970 with fractional seconds to time. (#31344)

    • Fix query hang or failure when calling hamming_distance() on strings containing a NUL character. (#31247)

    • Fix incorrect results and query failures when max_by() or min_by() with a count argument returns row values with null fields. (#31193)

    • Fix incorrect results for queries with a GROUP BY clause and multiple aggregations containing a DISTINCT clause when a grouping key is NULL. (#29095)

    • Fix incorrect NULL results from max_by() and min_by() with a count argument when the input contains NULL values. (#31383)

    • Fix incorrect results when filtering on a simple CASE expression with a NULL operand and a predicate in a WHEN clause. (#30992)

    • Fix incorrect results for window functions with a ROWS frame whose offsets vary between rows. (#31420)

    • ⚠️ Breaking change: Fix missing padding in SQL/JSON output for char values. (#30341)

    • ⚠️ Breaking change: Prevent precision loss when casting decimal-form JSON numbers to numeric types. (#30341)

    • ⚠️ Breaking change: Fix invalid JSON returned by json_array_get() when extracting string elements. (#28861)

    • Fix excessive CPU usage in clients that poll for query results right after a query finishes. (#31431)

    • Fix query failure when using BETWEEN SYMMETRIC with nested fields of row columns. (#31487)

    • Fix incorrect formatting of interval values when the JVM default locale uses non-ASCII digits. (#31433)

    • Fix duplicate rows in information_schema.tables when the table_name filter includes a table that does not exist. (#31488)

    • Fix query failure when variant values from arrays or UNNEST are used in GROUP BY, DISTINCT, IN subqueries, array_histogram(), or aggregation functions such as array_agg(), histogram(), and map_agg(). (#31387)

    • Prevent catalog properties, such as credentials, from appearing in error messages when a catalog is not available. (#31538)

    • Fix incorrect results for comparisons involving a cast from timestamp to timestamp with time zone with a lower precision. (#30496)

    • Fix incorrect results from date_diff() for timestamp(p) with time zone values with precision greater than 3 when the difference spans a daylight saving time transition or uses the month, quarter, or year unit. (#31543)

    • Fix incorrect rounding in to_unixtime() for timestamps with sub-millisecond precision, and in from_unixtime() for values halfway between milliseconds. (#31386)

    • Fix failures and incorrect results for timestamps near the maximum and minimum supported values. (#31564)
